SHOGUN Memory MCP setup

Wire agent clients to local Memory API over stdio (shogun-mcp). One job: copy commands and config. Source of truth: docs/memory-api-mcp.md and docs/examples/.

stdio only. Do not expose Memory MCP over HTTP. Streamable HTTP MCP is parked; stick to a local client spawning shogun-mcp on stdin/stdout.

1. Prerequisites

  1. Build the binary (from repo root): 
    cargo build -p shogun-core --features db --bin shogun-mcp --release
# → target/release/shogun-mcp
  2. In the SHOGUN desktop app: Settings → Memory API → On (writes memory_api.json; fail-closed if missing or off).
  3. Settings → Memory API → Issue a token. Copy once into the client env as SHOGUN_API_TOKEN.
  4. Point the client at the live DB (same folder as the running app).

DB paths (macOS)

Replace YOU with your home username. Use the path that matches the app you actually run.

# Product / shipping identifier
~/Library/Application Support/com.selectkk.shogun/memory.db
~/Library/Application Support/com.selectkk.shogun/memory_api.json

# Local spike / current desktop identifier (dev.shogun.spike)
~/Library/Application Support/dev.shogun.spike/memory.db
~/Library/Application Support/dev.shogun.spike/memory_api.json

Open Settings → Memory API once so memory_api.json exists next to the live DB. Standalone bins default DB to ./shogun.db unless SHOGUN_DB_PATH is set.

2. Auth (short)

  1. Enable Memory API in Settings → memory_api.json.
  2. Issue token in Settings → paste as SHOGUN_API_TOKEN in the client. Secrets live in Keychain (memory-api-tokens), not files.
  3. If any tokens exist, stdio MCP requires a matching token. If none yet, process-trust is allowed when enabled (dev DX).
  4. Encrypted DB: signed app can read Keychain account memory-db-key (service com.selectkk.shogun). Unsigned / cargo-built shogun-mcp may need SHOGUN_DB_KEY in the client env (hex from that Keychain item).

Optional: pull the DB key for unsigned debug (macOS Keychain):

security find-generic-password -s com.selectkk.shogun -a memory-db-key -w

Paste that hex into MCP env as SHOGUN_DB_KEY only when the unsigned binary cannot unlock Keychain itself.

3. Cursor

User or project MCP config. Example file: docs/examples/cursor-mcp.shogun.json. Typical location: Cursor Settings → MCP, or project .cursor/mcp.json / user ~/.cursor/mcp.json (exact path depends on Cursor version). 

{
  "mcpServers": {
    "shogun-memory": {
      "command": "/ABS/PATH/TO/ShogunAI-/target/release/shogun-mcp",
      "args": [],
      "env": {
        "SHOGUN_DB_PATH": "/Users/YOU/Library/Application Support/com.selectkk.shogun/memory.db",
        "SHOGUN_MEMORY_API_SETTINGS": "/Users/YOU/Library/Application Support/com.selectkk.shogun/memory_api.json",
        "SHOGUN_API_TOKEN": "shogun_PASTE_ISSUED_TOKEN"
      }
    }
  }
}

Spike DB: swap com.selectkk.shogun → dev.shogun.spike. Unsigned binary: add "SHOGUN_DB_KEY": "HEX_FROM_KEYCHAIN" under env.

5. Claude Code

No checked-in example under docs/examples/ yet. Best-effort from the same env contract as Cursor / Desktop (docs/memory-api-mcp.md). Confirm flag names with claude mcp --help on your CLI version.

CLI (best-effort)

claude mcp add shogun-memory \
  --env SHOGUN_DB_PATH="/Users/YOU/Library/Application Support/com.selectkk.shogun/memory.db" \
  --env SHOGUN_MEMORY_API_SETTINGS="/Users/YOU/Library/Application Support/com.selectkk.shogun/memory_api.json" \
  --env SHOGUN_API_TOKEN="shogun_PASTE_ISSUED_TOKEN" \
  -- /ABS/PATH/TO/ShogunAI-/target/release/shogun-mcp

JSON shape (same as other clients)

If your Claude Code setup uses an mcpServers JSON file, reuse the Cursor / Desktop block above.

6. Other agents

Checked under docs/examples/: Cursor and Claude Desktop only. No Windsurf / VS Code Copilot / Continue / Zed recipes in-repo yet. Any stdio MCP client that can set env vars can use the same command + three env keys (plus optional SHOGUN_DB_KEY).

7. Smoke check

  1. Enable Memory API + issue token.
  2. Point client at shogun-mcp with env vars.
  3. In agent chat: profile.whoami → memory.get_context → memory.append_note.
  4. Disable Memory API → restart MCP → process should refuse (stderr: disabled).

Gaps / not yet

  • Claude Code — no official example JSON in docs/examples/; CLI snippet is best-effort.
  • HTTP / network MCP — not supported for Memory; do not open a port for agents.
  • Live AX / Notch cache — standalone MCP sees DB-backed context only, not the live screen cache.
  • actions.execute — local kinds run (or authorize) immediately; external sends are L3: enqueued to the shared approval file (l3_approvals.json) and must be confirmed in Settings → Approvals before anything leaves the device.
