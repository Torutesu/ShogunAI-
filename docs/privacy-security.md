# プライバシーとセキュリティ

> この文書は SHOGUN が「何を・どこに保存し・何に使い・何には使わないか」を正確に説明する正典です。技術者・情報システム部門向けの説明資料として、Keychain / SQLite / Anthropic 等の必要な固有名は正確性のためそのまま記載します。
>
> **アプリ内からの導線**: 設定 → 「Privacy & Security」→ Data policy カードの「Read the full privacy policy」リンクから到達できます。現在このリンクは LP のプライバシーページ（`https://shogunai.app/privacy`）を指していますが、**公開 URL は確定前**です。最終的にはこの文書または LP の該当ページのいずれかを指します。

SHOGUN はローカルファーストの設計です。データの重心はデバイス上の Rust コアにあり、クラウドへ出るのは大規模 LLM の処理に必要なチャンクのみです。以下、その境界を具体的に示します。

---

## 1. 保存するデータと保存先

**大前提: SHOGUN は画像・音声・録画・スクリーンショットを一切保存しません。** 画面キャプチャは macOS の Accessibility API 経由で取得した**テキストのみ**です。会議の音声は**オンデバイスでのみ処理**し、波形は RAM から出ません（ディスク・一時ファイル・クラウドのいずれにも書きません）。永続化されるのは文字起こしテキストとその出所情報（provenance）だけです。

| データ種別 | ローカル SQLite（暗号化 DB） | macOS Keychain | クラウドへの送信 |
|---|---|---|---|
| 画面テキスト（Accessibility API 由来のテキスト） | 保存する | — | 処理用チャンクのみ（下記 §2 参照） |
| 会議の文字起こしテキスト | 保存する（テキストのみ／音声波形は保存しない） | — | 処理用チャンクのみ |
| メタデータ（アプリ名・ウィンドウタイトル・タイムスタンプ・滞在時間など） | 保存する | — | 処理に必要な範囲のみ |
| 抽出 state（`people` / `projects` / `commitments` / `open_loops`） | 保存する（各行に根拠イベント参照＋ confidence） | — | 処理に必要な範囲のみ |
| secrets（BYOK の LLM API キー・各連携の OAuth トークン・Composio API キー） | **書かない**（平文でファイル・DB・ログに残さない） | **ここにのみ保存** | 送信しない |

- ローカル DB は暗号化されています。DB の暗号鍵（`memory-db-key`）は Keychain に保管されます。
- **secrets は Keychain 以外に保存しません。** BYOK 鍵・OAuth トークン・Composio API キーは平文でファイル・DB・ログに書き出しません（絶対不変条件）。設定 UI でも設定済みキーは**末尾 4 桁のみ**を表示し、平文をアプリ本体（webview）へ渡しません。
- ログ・エラーレポート・テレメトリにはユーザーのキャプチャ内容を含めません。加えて多層防御として、ログ出力の境界でメールアドレス・完全 URL・API キー形状の文字列を強制的にマスクします。

---

## 2. ローカル / クラウド境界

「生データはデバイス外に出さない。クラウドへ出るのは処理用チャンクのみ」が原則です。クラウドへ送信する箇所は必ずトレーサビリティログに記録されます（内容そのものは残さず、ダイジェスト／フラグのみ）。

| ローカルで完結する処理 | クラウドへ送信する処理 |
|---|---|
| キャプチャ取得＋一次マスキング（書き込み前の redaction） | 大規模 LLM へのプロンプト（＝処理用チャンクのみ） |
| テキスト抽出などの軽量な前処理 | 送信は必ずトレーサビリティログに記録 |
| ローカル検索（全文検索・ベクトル検索） | — |
| オンデバイス文字起こし（会議 ASR） | — |
| ローカルメモリ（3 層メモリ・state tables） | — |
| 埋め込み生成（同梱のローカル ONNX モデル。クラウド embedding API は使わない） | — |

### モード比較

| モード | ローカル処理 | クラウド送信 | 位置づけ |
|---|---|---|---|
| ローカル優先 | すべての軽量処理・検索・メモリ | 大規模 LLM 推論に必要なチャンクのみ | 既定の考え方 |
| 標準（ローカル＋クラウド） | 同上 | LLM 推論に加え、ユーザーが有効化した連携での送信 | 通常運用 |
| 将来のローカル限定モード（構想） | すべて | ゼロ（クラウド送信を行わない） | **構想段階。本 Issue は境界定義まで。実装は将来**（§6 参照） |

## 3. モデル学習に使わない

**SHOGUN は、ユーザーの個人データを独自モデルの学習に使いません。**

送信先の LLM プロバイダ（v1 は Anthropic）についても、事実に基づいて正確に説明します。

- Anthropic API（BYOK・Select KK の Batch API とも）は、**商用規約上デフォルトで入出力をモデル学習に使いません。**
- 「学習させない」ための per-request（リクエスト単位の）ヘッダは**存在しません**。SHOGUN はそのようなヘッダを送っていません（存在しないため）。デフォルトで学習非利用であることが根拠です。
- Zero Data Retention（ZDR／ゼロデータ保持）は**エンタープライズ契約レベル**の設定であり、リクエストヘッダで切り替えられるものではありません。SHOGUN にとっては**将来課題**です。

### プロバイダ別の保持ポリシー

| プロバイダ | 学習利用 | 保持 | ZDR |
|---|---|---|---|
| Anthropic（BYOK／Select KK Batch） | デフォルトで**学習に利用しない** | 悪用監視の目的で**約 30 日**保持 | エンタープライズ契約レベルの設定。SHOGUN では将来課題 |

> 将来 v1 以降で他プロバイダ（例: OpenAI 等）を実装する際、そのプロバイダに学習利用のオプトアウト設定 API がある場合は**デフォルトで有効化**します（プロバイダ抽象化層にオプトアウトのフックを用意済み。v1 は Anthropic のみのため実質 no-op）。

## 4. データ削除

アプリ内（設定 → Privacy & Security → Delete data）から、いつでも以下を実行できます。

- **直近 1 時間** を削除
- **直近 24 時間** を削除
- **全削除 & アカウント削除**

### 削除の性質

- **ローカル即時削除**（数秒）。何もクラウドへ送りません（デバイス上での処理です）。
- **論理削除ではなく物理削除**です。`DELETE` で行を実際に消します（フラグを立てるだけの論理削除ではありません）。スキーマ（テーブル定義）は保持します。
- 時間範囲削除（1h / 24h）は、対象期間のイベント（`event_log`）と、その根拠を**すべて失った（孤児化した）** state 行のみを削除します。他の生存イベントに支えられている state は残ります。関連する全文検索インデックス・ベクトル・会議セッションとそのノート・トレーサビリティログも同期して削除されます。
- **全削除 & アカウント削除** は、上記に加えて Keychain から次を消します:
  - すべての BYOK 鍵
  - 接続済みサービスのすべての OAuth トークン
  - Composio API キー
  - なお、ローカル DB の暗号鍵（`memory-db-key`）は**意図的に保持**します。全削除後も DB を再利用可能に保つためです（スキーマは保持され、暗号鍵で引き続き開けます）。

### 正直な限界

削除には、こちらの制御が及ばない部分があります。隠さず明記します。

- **派生要約テキストへの残存**: `relationship_summary` のような、複数イベントから導出された要約テキストは、根拠イベントを削除した後も、**次回の Dream Cycle で再導出されるまで**、文言に影響が残り得ます。反映には時間がかかる場合があります。
- **ベンダーへ送信済みのデータ**: すでにクラウドの LLM プロバイダへ送信されたデータは、そのベンダーの保持ポリシーに従います（§3 のとおり、Anthropic は悪用監視目的で約 30 日）。**ベンダー側に削除 API が無い部分は、こちらからは消せません。** この点は正直にお伝えします。

---

## 5. 匿名統計

- **既定は OFF（オプトイン）** です。ユーザーが明示的に ON にしない限り、統計は一切送信しません。
- ON にした場合でも、送信されるのは**匿名・集約された統計のみ**です。**ユーザーのキャプチャ内容は決して含めません。**
- 設定からいつでも切り替えられます。

## 6. 将来: ローカル限定モード

クラウド送信をゼロにする「ローカル限定モード」を将来切り出せるよう、§2 のローカル / クラウド境界を土台に設計を分離しています。

- **本 Issue の範囲は境界定義まで**です。ローカル完結処理とクラウド送信処理を明確に分けることで、後からクラウド送信をゼロにするモードを要件レベルで切り出せる状態にしています。
- **実装は将来**であり、現時点では**構想段階**です（この文書で「構想」と明記します）。
