## 2. Phase 1 — 中継の堅牢化 / CI（`9b95d2e`）

- **日次上限が read-then-write だった**: 同時50投入が全部同じ `used` を読んで全通過する。
  reserve-then-commit に変更（回帰テスト: 上限10に同時50投入 → ちょうど10）。
  上流失敗時は解放するので、プロバイダ障害がユーザーの1日を食わない
- **台帳が壊れると全ライセンスのカウンタが 0 に戻っていた** ＝ 運営キーの唯一の支出制御が
  消える。読めない場合は 503 で fail-closed
- `MAX_ITEMS` / `MAX_CHUNK_BYTES` / `MAX_CUSTOM_ID_BYTES` と 8 MiB の `bodyLimit`（413）。
  無制限の `c.req.json()` は1リクエストで OOM させられる
- ライセンス単位のトークンバケット（既定 12 burst / 12 per minute）
- **CI のパスフィルタに `scripts/**` と `.github/workflows/**` が無かった** ＝ 不変条件ガードを
  弱める PR が CI を1本も走らせずに通る。`apps/api/**` も追加し、`batch relay` ジョブを新設
  （それまで `apps/api` は何も走っていなかった）
- Deepgram のトークン発行に**この端末のライセンストークンを bearer として提示**。
  mint URL の漏洩だけでは会社キーを溶かせない。mint URL は `https://` 必須

## 3. Phase 2 — 不変条件を「覚えておく」から「構造」へ（`3db2ffe`）

  DB 未初期化時に到達可能。必須依存に変更し、`voice_lane` は記録できないなら**送らずに止まる**
- ライセンス検証 / Stripe checkout / portal が `Route::Billing` を記録。こちらは best-effort

  ペイロードがユーザー本文である ASR とは逆の判断で、コメントにその理由を書いた）
- `billing.json` を**不変条件7 の明示的例外として CLAUDE.md に記録**。設計と実装の矛盾を
  放置しない。トークンは署名済み・device バインド・約24時間で失効するため秘密ではなく、
  ライセンス**キー**は Keychain のみのまま
- 新ガード `scripts/check-media-writes.py`（不変条件2）と `scripts/check-log-hygiene.py`

## 4. Phase 3 — 残存UXバグ（`2e43f47`）

- **実バグ**: Settings と `PrivacySecuritySection` が Agent lane の provider を別々に保持し、
  それぞれ自分の mount で取得していた。親カードで委譲先を選ぶと子が stale になり、
  `saveKey` は provider を**明示的に**渡すので、**BYOK キーが別プロバイダの Keychain
  アカウントに保存されていた**
- ショートカット表示が独自フォーマッタで、既定バインドを `Tap ⌥` / `Dual ⌘` という
  リテラル文字列で描いていた（同じ機体でオンボーディングが教えるのと違うショートカット）
- SLO-02 の計測が Hub トグルのたびに再 mount で新規サンプルを取っていた。expand ごとに1回
- **`rest::act` が `ApprovalSurface` を取る**: スタンドアロンの `shogun-api` / `shogun-mcp` は
  誰も drain しない承認キューを作るので、L3 送信が「受理」に見えて静かに期限切れしていた。
  501 `no_approval_surface` を返す。**不変条件4 は元から破れていない**（送信は実行されない）——
  これは不変条件6「APIの顔は人間の顔と同じに振る舞う」を正直に守る話。**既定を headless に**
  したので、将来のアプリ内APIは UI があることを宣言しなければならない
- 帰属不明の承認は `ui` ではなく `unknown`（バッジはセキュリティ開示。「あなたがやった」は
  間違え方として最悪）

## 5. Phase 4 — 品質債務（`15018d7`）

- 死んだコードの削除（`voice_chat`、`OcrGate::{new,reset}`、`strings.ts` の未使用42キー、
  死に CSS 37規則）。`capture_ptt_*` は存在しないモジュールを叩いていたので削除したが、
  **なぜその形のテレメトリだったか**の設計理由はコメントとして残した
- `[workspace.lints.rust] unused = "deny"`。**`warnings` 全体ではない** —— `warnings` は
  clippy の全 lint を WARN に昇格させ、意図的に warn にしてある `expect_used` まで巻き込む
- `with_programmatic_move` を Drop ガード化（内部の panic がフラグを掛けっぱなしにして
  そのセッションのドラッグ位置記憶を殺していた）
- `orphan_sql` は `unreachable!()` をやめて `Option` を返す（5つ目の state table は
  メンテスレッドをトランザクション途中で落とすのではなく skip されるべき）
- トレイアイコンの `.expect()` を `match` に。**失敗しても skip するのはトレイだけ**
  （早期 return だと DB 起動ごと飛ぶ）
- `event_log` の insert+index が**意図的に1トランザクションでない**理由を明文化
  （再構築可能なインデックスを守るためにイベントを巻き戻すのは、その経路が絶対に
  出してはいけない結果）
- **REST の顔が Host ヘッダを検証していなかった**: loopback バインドと Bearer は
  メモリデータを守るが、`/v1/status` と `/v1/metrics` は設計上オープンで、DNS リバインドした
  ページは same-origin。SLO スナップショットが任意のサイトから読めた。403 `forbidden_host`＋
  実ソケットでリバインド Host を流す回帰テスト
- API トークン比較を定数時間に

## 6. CI

| コミット | 結果 |
|---|---|
| `12d6fb3` | ✅ |
| `9b95d2e` | ✅ |
| `3db2ffe` | ✅ |
| `2e43f47` | ❌ → 追随修正 |
| `15018d7` | ❌（同一原因）→ 追随修正 |

Phase 3 の2つの意図的な挙動変更が、その挙動を assert していた箇所を壊した。どちらも
**新しい挙動が正しい**ので、テスト側を新しい意図に合わせた:

- `shogun_api.rs` の e2e が外部送信に 202 を期待していた → 501 `no_approval_surface`。
  「受理されない」ことと「pending と偽らない」ことの両方を assert する
- `draft_and_enqueue` が `origin` 追加で8引数になり `clippy::too_many_arguments`。
  `allow` ではなく `Draft<'_>` 構造体に4つの `&str` をまとめた（連続する4つの `&str` は
  取り違えが起きる形。`destination` と `subject` の入れ替わりは、送信先を件名にする）

`apps/desktop/src-tauri`（`shogun-desktop-spike`）は macOS 専用のため Linux 環境では
コンパイル検証できない。**macos-14 の CI が唯一の検証手段**であり、この2件はどちらも
そこでしか出ない失敗だった。
