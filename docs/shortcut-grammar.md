# トリガー文法 — 修飾キー + ジェスチャ

- 文書ID: `docs/shortcut-grammar.md`
- ステータス: 設計確定（フロントエンド実装済み / Rust側は §5 が未実装）
- 実装: `apps/desktop/src/shortcuts.ts`（モデル）、`src/ShortcutRows.tsx`（UI・記録）

## 1. なぜ文字キーをやめるのか

常駐オーバーレイのショートカットに文字キーを使うと、2つの問題が同時に起きる。

1. **覚えられない。** 「⌃⌥N」は調べ直すもの、「control+optionを2回」は1日で手が覚えるもの
2. **必ず衝突する。** どんな文字コードも、どこかのアプリでは誰かのショートカット。**キーを含まない修飾キーの組み合わせは、誰のものでもない**

そして、SHOGUN には**すでにこの文法の実例があった**。カーソル位置にドラフトを挿す ⌥ タップである。ところがコード上は「グローバルショートカットにできない特例なので再割り当て不可」と書かれていた。特例ではない。`Alt:tap` という、この文法の1文にすぎない。文法として書き下せば、他と同じように再割り当てできる。

文字コードは**廃止しない**。まれで取り返しのつかない操作（Quit）には、狙いを定める一瞬が**必要**だからである。

## 2. 文法

```
trigger := modifiers ( ":" gesture | "+" key )
modifiers := ( "Function" | "Control" | "Alt" | "Shift" | "Super" ) ( "+" ... )
gesture := "hold" | "tap" | "double"
```

- `Control+Alt:double` — ⌃⌥ を2回叩く
- `Alt:tap` — ⌥ を1回叩く
- `Function+Control:hold` — fn+⌃ を押し続ける
- `Control+Alt+KeyQ` — 従来のコード（gesture は `press`）。**既存の保存値がそのまま読める**

シリアライズは文字列なので、既存の `get_shortcuts` / `set_shortcut` コマンドがそのまま運べる。

### 認識のルール（Rust側が守るべき挙動）

| 事象 | 判定 |
|---|---|
| 修飾キーを押し、`HOLD_MS`(350ms) 以上保持してから離した | `hold` |
| 修飾キーを叩き、`DOUBLE_MS`(420ms) 以内にもう一度同じ組を叩いた | `double` |
| 修飾キーを叩き、420ms 経過した | `tap` |
| 修飾キー保持中に**実キーが押された** | 保留中の tap を**破棄**して `press`（コード） |

最後の行が重要。これがあるから `Alt:tap` と `Control+Alt+KeyQ` が同居できる。

### 影（shadow）

`⌃⌥:tap` は `⌃⌥:hold` と `⌃⌥:double` を飲み込む — tap はキーが離れた瞬間に発火するので、長いジェスチャに到達しない。UIは**警告するが禁止しない**（キーボードはユーザーのもの）。

コードチェイス（`⌃⌥+Q`）は tap に飲まれ**ない**（上表の最終行）。実装 `shadows()` はこの区別を持つ。

## 3. 既定値と、その根拠

| アクション | 既定 | 根拠 |
|---|---|---|
| `summon` — Show SHOGUN | `Control+Alt:double` | 1日20回やる操作なのでキーを1つも使わない。hold ではなく double にしたのは、⌃⌥ の保持はコードを打とうとして偶然起きるから |
| `draft` — Draft where you're typing | `Alt:tap` | 最速のジェスチャを、**打っている文を離れずに起きなければならない**操作に充てる。従来の挙動と同一 |
| `quit` — Quit | `Control+Alt+KeyQ` | 常駐アプリの終了は狙いを定める一瞬があってよい。ここは文字コードが正しい |

## 4. UI

`⌃` と `⌥` はキーボード上で最も混同される2つの記号で、この画面を読んでいる人はたいてい「今トリガーに失敗した人」である。だからチップは**グリフと単語の両方**を出す — `⌃ control`。

ジェスチャは**箱で囲まない**。囲むと「もう1つ押すキー」に見える。修飾キーを**修飾する**語なので、静かで、幅だけは常に確保する（`2×` の有無で行末が左右にずれないため）。

`fn` はWebViewから観測できない（WebKit が報告しない）。記録中だけ `fn` の**アーム用ボタン**を出す — 押させるのではなく、クリックで含める。これで fn を語彙から外さずに済む。

## 5. Rust 側の残作業

既存の ⌥タップ監視（`lib.rs` の CGEventTap）を、**一般の修飾キー・ジェスチャ認識器**に一般化する。必要なのは:

1. `flagsChanged` イベントから修飾キー集合の変化を追う（`NSEventModifierFlagFunction` を含む — fn はここで取れる）
2. §2 の表のとおり `hold` / `tap` / `double` / `press` を判定。タイマ定数は TS 側と共有する値にする（350 / 420ms）
3. `get_shortcuts` / `set_shortcut` は**そのまま**。運ぶ文字列の形が増えるだけ
4. 保存済みの旧形式（`Control+Alt+KeyN`）は `press` として動き続ける。マイグレーション不要
5. 影（§2）の解決順は `press` → `double` → `hold` → `tap`

計測: トリガー発火から Expanded 描画完了までは既存の SLO（100ms）に含まれる。ジェスチャ判定の待ち時間（tapの420ms）は**SLOの分子に入れない** — dwell と同じ理由で、誤発火対策のプロダクト判断であって描画性能ではない（`docs/notch-ui-prototype-spec.md` §1 Q2 と同じ扱い）。

## 6. 増やすときの指針

新しいアクションを足すときは、**まず既定を選べるか**を問う。選べないなら、それはショートカットに値しないアクションである可能性が高い。語彙は意図的に小さい:

- 常用する操作 → 修飾キー + ジェスチャ
- まれ・破壊的な操作 → 修飾キー + 文字キー
- **既定を持たないアクションを作らない**（ユーザーが設定して初めて存在する機能は、存在しないのと同じ）
