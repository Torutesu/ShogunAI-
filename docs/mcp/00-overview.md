## 重要な前提 2 つ

### 前提 1: 接続レイヤーの大部分は実装済み

Issue #59 は「MCP を繋ぐ仕組みがまだ存在しない」前提で書かれているが、**実際には接続レイヤーの大部分がすでに実装済み**である（2026-07 時点）。

- `crates/shogun-mcp` — 権限表・認可ゲート・接続状態機械・JSON-RPC サーバー（純ロジック、テスト済み）
- `crates/shogun-integrations` — 公式 MCP エンドポイント定義・OAuth 2.1+PKCE・トークン管理・Keychain・同期ランタイム
- 設計の正本は `docs/requirements-v1.0.md` §6.9〜6.10（FR-INT-01〜07 / FR-C2-01〜05）と、**CLAUDE.md「連携実装ルール」の 2026-07 決定（下記前提 2）**

したがって本ドキュメント群の役割は「ゼロからの設計」ではなく、

1. **現行設計の言語化** — コードに埋まっている設計判断＋記録済みのオーナー決定を、PM・ユーザー案内に使える形で取り出す
2. **案内の穴埋め** — ユーザー向けガイドとオンボーディング設計はまだ無いので、ここで定義する
3. **残作業の切り出し** — 未検証・未完成の部分（ライブ接続検証、Gmail 経路のコード移行、UI 仕上げ等）を後続 Issue にする

残作業の正確な区分は `01-architecture.md` の「未検証事項」を参照。「未実装」と「未検証」を混同しないこと。

### 前提 2:【2026-07 決定】Gmail は読み取り・ドラフト・送信のすべてを Composio 経由にする

当初の設計は「Gmail の読み取り/ドラフト＝公式 MCP 直結（第1層）、送信のみ Composio（第2層）」だった。しかし Gmail 公式リモート MCP は Developer Preview のままで**実接続できない確度が高く**、オーナー判断で Gmail を全面 Composio に寄せた（CLAUDE.md「連携実装ルール」に記録済み）。狙いは**実際に動く接続の確度と回答品質の最大化**であり、代償として**受信箱の内容が第三者（Composio）を経由する**ことを明示的に受容した決定である。よって以下を必須とする：

- Composio の使用（**読み取りを含む**）に **opt-in 同意（3開示）を必須**にする。**同意なしでは同期も送信も一切行わない**
- 送信は従来どおり **L3（人間の明示承認）**、かつ **draft-stop（既定 ON、同意後のみ OFF 可）**
- **読み取り egress にもトレーサビリティを記録**する（第三者境界。内容は残さずダイジェスト/フラグのみ）
- 認証情報のうち **Composio API キーは Keychain**、user id は非秘匿として設定 JSON（Google Cloud OAuth は Gmail には不要）

これは不変条件3（生データはデバイス外に出さない／第三者露出の最小化）に対する**明示的・記録済みの例外**。将来 Gmail 公式 MCP が GA になれば、読み取り/ドラフトを第1層（直結）へ戻す余地を残す。

⚠️ **コードの現状との差分**：`crates/` の Gmail 経路（`endpoints.rs` の第1層 Gmail エントリ、`send_bridge.rs` の「送信のみ第2層」ルーティング等）は**旧設計のまま**で、この決定への移行は残作業（`04-dev-implementation.md` §2 参照）。本ドキュメント群は決定後の設計を正として記述し、旧設計のままの箇所には都度その旨を注記する。

## 初期対応する MCP（Issue の「最大3〜5個」への回答）

段階導入（Wave 方式、FR-INT-03）がすでにコード化されている（`crates/shogun-mcp/src/scope.rs` の `Wave` enum）。

| Wave | サービス | 経路 | Issue のカテゴリ対応 | 状態 |
|---|---|---|---|---|
| **Wave 1（初期ローンチ）** | Google Calendar / Google Drive | 第1層（公式 MCP 直結） | カレンダー系・ドキュメント系 | 実装済み・ライブ検証待ち |
| **Wave 1（初期ローンチ）** | Gmail | **第2層（Composio 経由、読み取り・ドラフト・送信すべて。opt-in 3開示同意必須）** | メール系 | 第1層コードは実装済みだが 2026-07 決定により Composio 経路へ移行（移行実装＋ライブ検証が残作業） |
| Wave 2 | Slack | 第1層 | — | コードあり・未テスト |
| Wave 3 | Notion / GitHub / Linear | 第1層 | タスク・Issue 系 | コードあり・未テスト |

**初期対応は Wave 1 の 3 個**。Issue の「最大3〜5個」の枠に収まる。未リリースの Wave は認可ゲート（`service_gate::authorize_op`）が自動拒否し、UI では「Coming soon」表示になる。

## 用語定義

| 用語 | 意味 |
|---|---|
| **第1層** | 各サービスの**公式リモート MCP サーバーに直結**する経路。中間サーバー無し（FR-INT-01）。Calendar / Drive（および Wave 2/3）の読み取り同期と書き込みの基本経路 |
| **第2層** | **Composio 経由**の経路。**現状は Gmail の読み取り・ドラフト・送信のすべて**（2026-07 決定）。オプトイン（3開示）必須で、第三者経由であることを UI に明示する（FR-C2-01〜05） |
| **3開示** | Composio オプトイン時に提示・承諾必須の3つの開示（FR-C2-02、`composio.rs` の `Disclosures`）：①データが第三者（Composio）を経由すること ②どの種別のデータが経由するか ③同意はいつでも取り消せること。3つすべての承諾なしに同意は成立しない |
| **Wave** | サービスの段階導入スケジュール。Wave 1 → 2 → 3 の順でしか解放されない |
| **接続状態（FSM）** | サービスごとの `connected` / `amber`（トークン失効など要再認可） / `disconnected` の状態機械 |
| **L3** | 外部への送信・書き込みに必須の人間承認レベル。承認キューを通らない外部送信は存在しない |
| **draft-stop** | Gmail 送信を「下書き作成まで」で止める安全設定。**既定 ON**（FR-C2-03）。OFF にできるのはオプトイン同意後のみ |
| **スコープ表** | `scope.rs` にある「サービス × Wave × 操作」の権限表。**表にない操作はすべて拒否**。権限の唯一の中心 |
| **オプトイン** | Composio（第2層）利用の明示的同意（3開示）。**同意なしでは第2層の同期（Gmail 読み取りを含む）・送信はすべてスキップされる** |

## スコープ / Non-Goal

**このドキュメント群でやること：**

- MCP 接続レイヤーの全体像を、実コードおよび 2026-07 決定と対応づけて言語化する
- ユーザー向けの接続フロー（オンボーディング・設定画面）を定義する
- モデル（Claude）側から見た MCP 利用の設計（一覧の渡し方・呼び出し優先度）をまとめる
- 後続の実装 Issue を切り出せる状態にする

**やらないこと（Non-Goal）：**

- Wave 2/3 を含む 7 サービス以上の同時サポート設計（初期は Wave 1 の 3 個に集中）
- MCP プロトコル仕様そのものの解説や、各外部サービスの詳細 API 設計
- UI のビジュアルデザイン確定（ワイヤー骨格まで。仕上げは Figma / 別 Issue）

## 設計の核（詳細は 01-architecture.md）

1. **第1層 / 第2層の分離** — 公式 MCP 直結を基本とし（Calendar / Drive）、第三者（Composio）経由は例外として厳格に管理する。Gmail は公式 MCP が Developer Preview で実接続確度が低いため、**接続確度と回答品質を優先して全面 Composio**（2026-07 決定、記録済み例外）。第三者経由は必ずオプトイン（3開示）＋UI 明示。Gmail 公式 MCP が GA になれば読み取り/ドラフトを第1層へ戻す
2. **Wave 段階導入** — 少数のサービスを確実に動かしてから次を解放する。コードで順序を強制
3. **トレーサビリティ** — 外部とのやり取りは本文なしのダイジェストで記録し、ユーザーが後から確認できる。**第三者（Composio）経由は読み取り egress も記録対象**で、UI に「第三者経由」バッジを明示する
4. **秘匿情報は Keychain のみ** — OAuth トークン・API キーは macOS Keychain に保存。設定ファイルには置かない（Composio の user id のみ非秘匿として設定 JSON）
